# 本地现实时间接回（beta.3预览）

本地Node进程保存绝对Unix毫秒到期时间。每秒只检查本机时钟与数据库，不按每次回调次数扣减倒计时。电脑睡眠使回调暂停；恢复后即使已超期，下一次回调仍处理到期任务。任务不会因错过某一分钟而丢失，也不因超期直接发送。关机、程序退出或两端停止运行不在本轮保证范围。无需保持屏幕常亮或主动唤醒电脑。

到期先通过已安装官方CLI的app-server proxy连接现有后台，正确完成WebSocket及initialize握手，查询account/rateLimits/read。真实双窗口与准入政策复用现有quota模块；本地查询单独标记codex-app-server-read，不冒充原生MCP钩子证据。未知、过期、账户禁用、任一窗口未达到恢复预留时等待，不启动模型、不使用重置券或额外计费API。

额度满足后thread/read与最近轮次检查实际忙闲，发送前再次核对。active、等待审批或错误时保留任务等待。notLoaded不能当空闲：仅持久化一次正常原生队列项，让原桌面所有者处理；本程序不调用thread/resume、start或steer，不创建对话或修改权限。当前用户已确认此项可进入桌面原对话待发送队列，但当前轮次未结束时不会自动打断。Windows任务计划程序不是运行依赖，本版使用用户权限隐藏后台进程；没有安装系统服务或新增系统计划。

## 使用

在工程根目录运行以下命令。一般由GPT自动填写原对话、当前已授权任务、指令和真实重置时间，用户无需填写编号。此处仅示例：

```powershell
node scripts/wake.mjs schedule --thread EXISTING_THREAD_UUID --task CURRENT_TASK --after-seconds 20 --message "检查额度并接续本任务" --detached
node scripts/wake.mjs status
node scripts/wake.mjs cancel --id WAKE_JOB_UUID
node scripts/wake.mjs inspect --thread EXISTING_THREAD_UUID
```

正式等待用带时区的ISO时间 `--at` 替代 `--after-seconds`，两者互斥。`--policy`读取现有tools配置中的quotaPolicy，默认仍为恢复40%，没有把20秒写成正式间隔。状态默认保存在本安装目录.local/runtime/wake，避免分享到发行包。所有受管路径拒绝符号链接。

重复登记同一原对话、同一任务的未结束计时会返回既有job、request及原到期时间，不重复创建。消息或策略不同则报冲突，不能悄悄覆盖。可用`--key`指定稳定幂等键：相同键即使计时已结束也返回旧登记，消息、策略或绝对到期时间不同则拒绝。固定键配合`--at`使用；新的复查周期使用新的键。

收到原对话消息后，GPT按消息携带的entry及args运行ack。它携带请求、任务和原对话绑定资料；ack仅证明消息被原对话读取，不代表Harness成果验收通过。之后照常真实原生额度核对、收取和实际验收。取消不自动撤回已经发送的消息；已发送状态要对账，不能假称已撤销。

ack还通过原生轮次摘要核对发起用户消息的clientId及完整正文，必须匹配原登记请求。人工复制、引用或修改过的消息均不能作为自动接回证明。只读取本原对话最近最多60轮的摘要，不获取推理或工具正文；无法核实时保留现场，不冒充成功。该核对面向启动新轮次的自动接回，不能保证识别用户改写后或被并入旧轮次中部的消息。

## 回执及故障

scheduled/pending只是计时登记；quota-wait、busy和host-unavailable明确说明尚未发起；dispatching在发送前持久化唯一clientUserMessageId；queued只是原生接受；started/completed需原对话真实回执。未知网络结果不能换请求编号重发。多个检查用数据库事务争抢一次发送权；同一运行目录只允许一个存活runner，睡眠期间不靠过期租约抢占它。

正常原生或界面排队不设固定失败期限，忙碌期间等待，不重复提交。队列项消失也不等于模型已开始，仍等待原对话真实ack；网络结果不明确时保留现场，不自动重发。真正的睡眠测试尚需用户设备实际睡眠/恢复验证；时间跳跃和过期到期的本地测试不能冒充物理睡眠实测。

已确认入队后，暂时无法查询队列不使发送结果退回未发送；保留queued/started状态，稍后只查回执，不重新发送。完成回执、取消、明确失败等终态不被延迟的查询或发送响应覆盖；started也不能倒退为queued。

## 当前客户端限制

官方命令存在不等于必定唤醒当前桌面对话。维护者在 https://github.com/openai/codex/issues/44491 明确说明queue对未加载线程只持久化消息，不恢复执行。桌面自有后台与CLI共享后台也可能分开：一个报告当前对话active，另一个报告notLoaded。本机实际队列投递已到达桌面输入队列，忙碌中继续等待；其他版本或卸载状态不能据此保证自动执行。不能删除写入锁或抢占桌面进程。

早期单次诊断的`queueProbe`仅保留为历史证据，不改变正式额度预留、计时或执行期限。后续使用正常schedule即可，无需此诊断标志。未执行的正常队列项可能等待桌面所有者处理，未知只对账，不重复添加。

本地程序的时钟、额度查询、正常排队与实际原对话唤醒必须分别验证。不要用本地测试通过或queued回执宣传完整自动恢复。
