# 转交前选择（beta.4）

真实额度触发原有阈值且有未完成的已授权任务时，GPT先调用handoff_confirm。原生MCP表单显示任务名称与“立即转交/暂不转交”，并说明30秒未回答会自动开始。点击立即转交会立即放行；明确拒绝或取消后本次不会打包、建立Harness聊天或派发。

30秒由本地程序和MCP请求超时控制，等待期间不运行模型，不创建额外定时。超时放行只授权继续当前任务的现有打包转交流程，不扩大文件范围、修改阈值或表示任务已完成。

确认按原对话和稳定任务编号持久记录；并发调用不会重复询问，重启后的未知等待记录也不会仅凭时间自动放行。拒绝不会因下一张额度票据再次弹窗。用户明确说重新选择时可reconsider=true重新询问；真实额度恢复后再次触发阈值也会重新询问。

询问通道不支持、连接出错或原轮次中断时保留进度，不将故障当作用户未回答。取消属于拒绝。确认通过后仍须检查新鲜额度、任务状态、文件授权及幂等执行记录。

使用标准MCP elicitation/create form及关联原工具请求；需要宿主支持表单询问。参见[官方App Server说明](https://learn.chatgpt.com/docs/app-server)。部署后正常重开GPT以加载新增工具；capabilities的handoffConfirmation同时区分配置启用与当前连接是否支持表单。真实桌面弹窗及默认转交仍需加载后的正常任务验证。
