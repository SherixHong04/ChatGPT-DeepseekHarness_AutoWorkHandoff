# 正常任务流程

1. 用户在任一受支持的工程或无工程原GPT对话开始工作。正常事件钩子提示查询真实额度，模型调用原生工具，完成钩子保存真实双窗口；未知、过期和重置后不猜测恢复。监测不登记文件访问范围，普通答疑不会因此创建工人任务。
2. GPT根据当前任务和真实额度决定继续或交接。程序使用配置中的保守预留，非精确任务预算估计。自动整理要求、进展、已引用文件、剩余工作和验收标准，publish同时补齐目录及文件指纹并逐任务登记。工程内可只用文件名，附件沿用已有路径，无文件任务自动保存摘要。仅确实无法消歧时合并一次询问；不让用户填写路径或重复确认每个项目。
3. chat_prepare/status确认新聊天在“GPT交接”工作区，固定幂等键enqueue，dispatch明确plan.outputs和deletions。接收结果未知只对账，不重发。
4. Harness只编辑副本。原GPT可独立处理其他工作，用户可在Harness同聊天继续推进；不实行系统级互斥或强制隔离。
5. 用户授权后，用宿主原生工具创建或更新绑定本任务原对话的接回调度。按真实额度重置时间安排，时间到仍重新查余额；记录真实调度ID，不能以计划提示冒充已创建。
6. managed_inspect发现活动或未完成轮次时保留现场、顺延本条复查约15分钟、无变化保持安静。复查间隔不限制执行时长；不做常驻高频守护或休眠唤醒。
7. 空闲且完成后managed_collect读取最新用户要求和实体快照。实际审查和测试在独立验收副本进行，不能只信模型自述。
8. 用户验收期间继续工作则暂缓旧版写回。若存在未应用的旧prepared提交，先rollback释放准备；新一轮稳定后再次collect，登记观察到的新成果而不发送模型指令、不增加自动返工次数。旧审批不能用于新成果。
9. 通过后review、prepare_commit核对备份、apply_commit写回、complete普通归档。原件冲突保留现场；归档失败只报告整理待完成，不重派或重复提交。

用户尚未发送的输入或思考无法可靠检测。检查序号和文件哈希可拦截已观察到的变化，不能宣称原子锁定了跨进程用户活动。正式长期使用前应覆盖用户真实续聊和升级场景。

停止：任务完成、取消、用户暂停、明确期限到达或需人工核实的未知执行时停止本任务调度；其他任务与旧聊天保持不变。没有默认模型执行时限，没有把90%/10分钟测试参数保留为正式默认。
